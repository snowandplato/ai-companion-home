# 第一次在本机试运行

这份草稿目前适合在自己电脑上试运行。**不要把网关端口直接开放到互联网。** 前端的演示口令写在网页构建产物中，不是服务器登录保护；管理接口也没有统一的身份验证。

## 1. 启动网关

本轮检查使用 Python 3.12。前端需要 Node.js 20.19+ 或 22.12+（Vite 的版本要求）。模型分工与配置对应关系见[配置与数据说明](配置与数据说明.md)。

在 `gateway` 文件夹中创建 Python 虚拟环境，安装 `requirements.txt`，把 `env.example` 复制成 `.env`。初次本地试运行保持 `API_HOST=127.0.0.1`。随后运行 `python main.py`；默认网关地址是 `http://localhost:8000`。

聊天所用的 API Key 与模型可以在前端设置里选择；每日总结、图片理解、画室等附加功能仍需要在 `.env` 中分别配置对应服务。先只测试普通聊天时，可以暂时不启用这些功能。

## 2. 启动前端

在 `frontend` 文件夹运行 `npm ci`，把 `.env.example` 复制成 `.env`，然后运行 `npm run dev`。浏览器打开开发服务器显示的本地地址，默认通常是 `http://localhost:5173`。前端设置里的网关地址使用 `http://localhost:8000`。

前端演示口令默认为 `change-me`。它仅用于挡住随手点开页面的人；**不要靠它保护已经联网的私人聊天或管理接口**。

## 3. 填写称呼和 System Core

在前端设置里保存助手与用户的称呼。System Core 和普通 Profiles 在后台填写，可以参考[填写示例](填写示例.md)。改名不会自动修改手写的 System Core，也不会重写历史记录。

本地打开后台的一种方法：在公开仓库根目录运行 `python -m http.server 5174 --bind 127.0.0.1`，再访问 `http://localhost:5174/admin.html`。这个临时文件服务器仅供本机查看后台；不要把整个源码目录作为公网静态站点，因为其中可能包含部署后创建的 `.env` 和数据文件。这个页面默认连接 `http://localhost:8000`。如果改了本地端口或网页来源，需要相应修改后台的网关地址与 `.env` 里的 `CORS_ORIGINS`。

## 准备远程访问时

远程访问需要先设计服务器端身份验证，并使用 HTTPS 与受保护的反向代理。只修改 `VITE_DEMO_PASSWORD`、开放 `API_HOST=0.0.0.0` 或把跨域来源改为 `*`，都不能代替这个步骤。完成后再根据实际站点设置网关地址与允许的网页来源。
